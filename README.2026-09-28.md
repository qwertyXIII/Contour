# Contour — VPN-контуры для процессов на сервере

> Обновлено: 2026-09-28 · Статус: **проектное описание, кода ещё нет**

Программа поднимает на сервере **контуры** — изолированные сетевые пространства
с VPN-туннелем внутри — и даёт каждому процессу машины выйти в интернет через
туннель **по желанию**, не переводя под VPN всю машину. Внутри контура работает
прокси. Кто хочет в туннель, идёт через него явно: Alter, AIPROXY, `yt-dlp`,
`curl`, любое другое приложение. Кто не хочет — ходит напрямую, как раньше.

Родилось из разбора «Интернет для Alter'а» (`~/project/Subpersonality/docs/devs/researchs/2026-09-28-internet-dlya-altera.md`, §8).
Решения владельца 2026-09-28:
- VPN — локальным прокси, а не маршрутом всей машины;
- туннелем пользуются и другие процессы;
- программа поддерживает разные протоколы VPN;
- ключи AmneziaWG — те же, что у AIPROXY; OpenVPN поддерживается сразу, ключ — когда-нибудь потом;
- у программы небольшой веб-интерфейс: закинуть ключи, управлять, смотреть, что происходит.

## 1. Что уже есть на сервере — и что из этого берём

AIPROXY (`/opt/aiproxy`, пользователь `aiproxy`, systemd) уже держит один
контур — **`aivpn`**:

```
┌─ корневой namespace ─────────┐   ┌─ netns aivpn ───────────────┐
│  alter :4100                 │   │  awg0 ──► туннель наружу    │
│  ещё 12 приложений           │   │  aiproxy :4110              │
│  10.200.0.1 ═══════veth════════► │  10.200.0.2                 │
└──────────────────────────────┘   └─────────────────────────────┘
```

- `aivpn-netns.service` → `/opt/aiproxy/deploy/vpn/setup-netns.sh up|down|status`
  (root): namespace, свой `/etc/netns/aivpn/resolv.conf`, туннель AmneziaWG
  (`awg0`, модуль ядра `amneziawg` загружен), мост `veth-ai` `10.200.0.1/30` ↔
  `veth-ai-ns` `10.200.0.2/30`.
- **Выключатель по построению**: внутри контура маршрута мимо туннеля нет — упал
  `awg0`, запросы честно падают, а не утекают.
- `aiproxy.service` живёт внутри через `NetworkNamespacePath=/var/run/netns/aivpn`
  и слушает `10.200.0.2:4110`.
- Ключ — `/etc/aiproxy/awg0.conf` (root, 600).

**Это ровно та форма, что нужна.** Не хватает трёх вещей: прокси внутри контура,
протоколов кроме AmneziaWG и управления с экраном.

⚠️ **AIPROXY гасится совсем** (решение владельца 2026-09-28): `aiproxy.service` и
`aiproxy-panel.service` — стоп и из автозагрузки. **`aivpn-netns.service`
остаётся**: это и есть контур, который программа перенимает. Скрипт контура и
ключ лежат в `/opt/aiproxy/deploy/vpn/setup-netns.sh` и `/etc/aiproxy/awg0.conf` —
`/opt/aiproxy` не удалять, пока программа их не переняла (шаг 2).

### ⚠️ Один ключ — один контур

WireGuard (и AmneziaWG) помнит у пира **один** адрес отправителя и переключается
на того, кто последним прислал пакет. Два туннеля с одним ключом с одной машины
(разные UDP-порты) будут выбивать друг друга: отвечать сервер будет то одному,
то другому. Поэтому «ключ тот же, что у AIPROXY» значит **один общий контур для
AIPROXY и Alter'а**, а не второй туннель рядом. С тех пор как AIPROXY гасится,
потребитель один — Alter, и вопрос снят, пока второй контур не заведут с тем же
ключом.

То же предупреждение есть в README AIPROXY про ключ, совпадающий с ключом
устройств владельца. Если у сервера и ноутбука один ключ, обрывы будут и там,
и чем больше ходит Alter, тем чаще. Лечится отдельным ключом для сервера в
панели Amnezia.

## 2. Модель

**Контур** = namespace + туннель одного протокола + мост veth + резолвер + прокси.

| Поле | Пример | Зачем |
|---|---|---|
| `name` | `aivpn` | имя namespace; у существующего — прежнее, чтобы AIPROXY не заметил переезда |
| `protocol` | `amneziawg` / `wireguard` / `openvpn` | чем поднимать туннель |
| `key` | ссылка на загруженный файл ключа | конфиг туннеля |
| `bridge` | `10.200.0.0/30` | адреса моста: `.1` — хост, `.2` — внутри |
| `dns` | из конфига или `1.1.1.1` | резолвер внутри контура |
| `proxy.port` | `3128` | где слушает прокси внутри, на адресе `.2` |
| `enabled` | `true` | поднимать ли при старте |

Контуров может быть несколько (разные страны, запасной сервер), и потребитель
выбирает контур адресом прокси.

### Протоколы

| Протокол | Чем | Замечания |
|---|---|---|
| AmneziaWG | `awg` / `awg-quick` внутри namespace | как сейчас в `setup-netns.sh`; ключ — `.conf` или ссылка `vpn://` из Amnezia |
| WireGuard | `wg` / `wg-quick` | тот же путь, без параметров маскировки |
| OpenVPN | `openvpn --config … --dev tun` в namespace | DNS приходит от сервера (`dhcp-option DNS`) — скрипт `up` пишет его в `resolv.conf` контура; ключ — `.ovpn`. Поддержка сразу, ключа пока нет |
| потом: VLESS / Reality / Shadowsocks | `sing-box` с входом `tun` внутри namespace | если понадобится |

Все требуют root (namespace, интерфейсы, маршруты). Это нормально — см. §4.

### Прокси внутри контура

- **HTTP CONNECT** (и обычный HTTP-проброс) на `10.200.0.2:<порт>` — его понимают
  `undici` (Alter), `curl -x`, `yt-dlp --proxy`, pip, git. SOCKS5 — если
  понадобится кому-то, кто не умеет HTTP-прокси.
- Маленькая программа без зависимостей, запускается внутри namespace (systemd
  `NetworkNamespacePath`), от непривилегированного пользователя.
- **Ограда в самом прокси** — не пускает в частные адреса: `127/8`, `10/8`,
  `172.16/12`, `192.168/16`, `100.64/10`, `169.254/16`, IPv6-локальные, а
  особенно адрес моста хоста `10.200.0.1` — изнутри контура это вся наша машина
  с её портами на `0.0.0.0`. Потребители проверяют адрес и сами (Alter —
  обязательно), но прокси не должен полагаться на то, что все проверяют.
- **Потребители — с токенами** (`Proxy-Authorization`): контуром пользуются
  несколько процессов, и на машине живут чужие приложения. Токен даёт и
  допуск, и счётчики на экране («Alter — 1,2 ГБ за сутки, yt-dlp — 300 МБ»).
  Без токена — отказ `407`.

## 3. Веб-интерфейс

Небольшой, для владельца:

- **Контуры**: поднят ли, возраст последнего рукопожатия, **внешний IP изнутри**
  («а точно через VPN?» — главный ответ), байты туда-обратно, задержка до
  проверочного адреса.
- **Ключи**: загрузить AmneziaWG `.conf` или `vpn://`, WireGuard `.conf`,
  OpenVPN `.ovpn`. Ключ хранится с правами `600` у root. На экране показывается
  только маска и откуда ключ: сервер, страна, когда загружен. Целиком ключ не
  показывается никогда.
- **Управление**: поднять, погасить, перезапустить контур; сменить ключ или протокол.
- **Потребители**: выдать и отозвать токен, трафик по каждому.
- **Журнал**: подъёмы, падения, переподключения, отказы ограды.

⚠️ Экран управляет VPN-ключами, поэтому наружу без защиты его не выставлять.
Слушает `127.0.0.1` на хосте. Как до него дотянуться — вопрос §6: ssh-тоннель,
nginx с входом или раздел в панели Alter'а.

## 4. Устройство и права

Namespace, интерфейсы и туннели — root. Веб-экран от root — плохо: дыра в
экране становится root на машине. Поэтому две части:

- **Демон** (root, systemd): держит контуры, поднимает и гасит, читает состояние.
  Наружу слушает только **unix-сокет** с правами на группу `contour`.
- **Экран** (непривилегированный пользователь `contour`, systemd): веб на
  `127.0.0.1`, говорит с демоном через сокет. Ключи передаёт демону, сам их не
  хранит.
- **Прокси** контура — отдельный непривилегированный процесс внутри namespace.

Код — по образцу `setup-netns.sh` (он идемпотентный, проверяет результат и
падает громко, а не делает вид). Язык — TypeScript на своём Node, как у AIPROXY
(`/opt/node-aiproxy`): системный Node 20 не трогаем, на нём чужие приложения.
Операции с сетью — `ip`, `awg`, `wg`, `openvpn`.

⚠️ На сервере нет sudo без пароля: установка и обновление — командами для
владельца, через `ssh -t`.

## 5. Порядок работ

1. **Прокси в существующий `aivpn`.** Один unit с `NetworkNamespacePath=/var/run/netns/aivpn`
   и прокси на `10.200.0.2:3128`. Туннель и ключ не трогаем. Alter получает туннель сразу.
2. **Демон перенимает контур.** `aivpn` поднимает уже программа, с тем же именем
   namespace и тем же ключом; `aivpn-netns.service` заменяется её unit'ом, скрипт
   и ключ переезжают из `/opt/aiproxy`, после чего `/opt/aiproxy` можно удалить.
3. **Протоколы**: WireGuard, OpenVPN (ключ потом), дальше по надобности.
4. **Экран**: состояние, ключи, управление, потребители, журнал.
5. **Потребители с токенами** и счётчики.

Каждый шаг выкатывается сам; после первого у Alter'а уже есть туннель.

## 6. Связь с Alter'ом

- Alter знает только **адрес прокси и свой токен** — настройка в его панели
  («Туннель»). Пусто — ходит только напрямую.
- Что пускать в туннель, решает Alter: сначала напрямую, с коротким таймаутом на
  соединение; не вышло — повтор через туннель, и сайт запоминается «только через
  туннель» на несколько дней. Плюс ручной список сайтов. Русские сайты, которые
  режут заграничные IP, остаются напрямую.
- Ограду адресов Alter держит сам — до туннеля, и отдаёт туннелю уже
  проверенный IP.
- Прокси Telegram (`telegram.proxy` в Alter'е) — отдельная вещь, только для
  Telegram. Contour его не заменяет.

## Открытые вопросы

- Как владелец заходит на экран: ssh-тоннель, nginx с входом или раздел в панели Alter'а?
- Потребители с токенами — сразу или после первого шага?
- Отдельный ключ AmneziaWG для сервера: сейчас он, возможно, общий с устройствами владельца.
- Где держать исходники: здесь, в `~/project/Contour`, с установкой в `/opt/contour`, как AIPROXY?
- Нужен ли SOCKS5, или HTTP CONNECT хватит всем потребителям.
